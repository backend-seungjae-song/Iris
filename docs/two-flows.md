# 개발 환경과 설치 앱의 분리

이 저장소는 같은 코드를 개발 환경과 설치 앱에서 실행한다. 명령 대상과 사용자 데이터가 섞이지
않도록 포트·프로필·상태 폴더를 분리한다.

| | 개발 | 설치된 앱 |
|---|---|---|
| 실행 코드 | 저장소 소스 | `/Applications/Iris.app` 안의 번들 |
| 포트 | 4291 | 4271 |
| 서버 실행 방식 | `pnpm dev`, 없으면 `pnpm dev:app`이 직접 실행 | 앱이 자식 프로세스로 실행 |
| 앱 실행 명령 | `pnpm dev:app` | `open -a Iris` |
| 프로필 | `~/Library/Application Support/Iris-dev` | `~/Library/Application Support/Iris` |
| 상태·증거 | `~/.iris-dev/` | `~/.iris/` |
| 코드 변경 반영 | 다시 실행 | `pnpm install:app` 으로 빌드·교체 |

## 설계 이유

서버에는 브라우저 실행기 슬롯이 하나다. 다른 인스턴스가 기존 실행기를 대체하면 명령 대상이
바뀐다. 확인 결과: 종료되지 않은 개발 인스턴스로 명령이 전달되어, 설치 앱이 지원하는 명령도
"알 수 없는 명령"으로 응답했다.

다음 규칙으로 환경을 분리한다.

- 포트를 분리한다. 앱은 `IRIS_PORT`로 연결할 포트를 정한다(기본 4271). `pnpm dev`·`pnpm dev:app`은
  4291로 고정되어 설치 앱의 포트에 연결하지 않는다.
- 중복 연결을 거절한다. 같은 포트에 다른 앱이 연결하면 서버가 나중 연결을 거절하고 기존 앱의
  경로·pid를 알린다. 거절된 앱은 콘솔에 "자기 포트로 도세요"를 남긴다. 같은 프로세스의 재접속은
  허용한다.
- 상태를 분리한다. 탭 기록·메모·지목·로그인·QA 회차 장부·매크로는 모두 `IRIS_STATE_DIR` 아래에
  저장한다(기본 `~/.iris`). 개발 환경은 `~/.iris-dev`를 쓴다. 같은 폴더를 쓰면 증거의 실행 환경을
  구별할 수 없다. 상태 경로를 직접 지정하면 이 분리가 우회된다. `browser-state.js`·`space-key.js`의
  직접 지정 경로 때문에 개발 서버가 설치 앱의 북마크·탭·스페이스 키 파일을 사용했다.
  상태를 쓰는 모든 파일은 `bin/smoke.mjs`의 "상태 경로를 손으로 다시 짜지 않는다" 목록에 포함한다.
- 상태 폴더는 서버 하나만 사용한다. 바인딩 주소가 `0.0.0.0`과 `127.0.0.1`이면 포트가 같아도
  서버 둘이 실행될 수 있다. 같은 상태 파일을 쓰면 먼저 실행된 서버가 최신 상태를 오래된 상태로
  덮어쓸 수 있다. 확인 결과: 종료되지 않은 서버 프로세스가 복원한 계정·검색 기록·탭을 반복해서
  삭제했다. `IRIS_STATE_DIR/server.lock`을 획득한 서버만 실행하고, 획득하지 못한 서버는 현재
  사용 중인 프로세스를 알린 뒤 종료한다.

## 서버 프로세스는 앱이 관리한다

앱은 시작할 때 서버를 자식 프로세스로 실행하고 종료 시 함께 종료한다
(`native/electron/server-host.cjs`). 이 구조는 launchd가 저장소 소스로 서버를 실행할 때의
다음 제약을 해결한다.

- 저장소가 없는 사용자도 앱만 설치하면 실행할 수 있어야 한다.
- 앱 재시작 시 서버도 재시작하여 변경 사항을 반영해야 한다.
- 서버 실행 실패가 무한 반복되지 않아야 한다. 확인 결과: KeepAlive가 재기동을 6,957회 반복하는
  동안 관리 대상 서버는 한 번도 실행되지 못했다. 앱은 서버가 60초에 5번 종료되면 재시도를 멈추고
  `IRIS_STATE_DIR/server.log`를 안내한다.

다음 두 조건을 유지한다.

- 이미 실행 중인 서버는 종료하지 않는다. 앱은 시작 시 `/healthz`에 응답하는 서버가 있으면
  연결만 한다. 기존 서버를 교체하면 사용자의 탭·계정·로그인 상태가 유실될 수 있다.
  앱 종료 시에도 자신이 실행한 서버만 종료한다.
- 설치 앱에 서버 소스와 화면을 함께 포함한다. 자식 프로세스는 asar 안의 파일을 열 수 없으므로
  `server/`·`web/`·`node_modules/`를 asar 밖에 배치한다. 설치 앱은 Electron을 런타임으로 사용하므로
  (`ELECTRON_RUN_AS_NODE`) 기기에 node가 없어도 실행된다. 개발 환경은 저장소의 `node_modules`가
  시스템 node의 ABI로 설치되어 있으므로 시스템 node를 쓴다.

이전 launchd 방식에서 전환하는 기기는 다음 순서를 따른다. 순서를 바꾸면 서버가 실행되지 않는
시간이 생긴다. `<잡>`은 해당 기기의 launchd 잡 이름이며 `ls ~/Library/LaunchAgents`로 확인한다.

```
launchctl bootout gui/$UID/<잡> # 1. 이전 관리 주체를 내린다
mv ~/Library/LaunchAgents/<잡>.plist \
 ~/Library/LaunchAgents/<잡>.plist.disabled # 2. 재부팅해도 안 돌아오게
osascript -e 'tell application "Iris" to quit' && open -a Iris # 3. 앱을 다시 실행한다. 이후 서버는 앱이 실행한다
curl -s http://127.0.0.1:4271/healthz # 4. 관리 주체가 바뀌었는지 확인한다
```

4번 응답의 `pid`에 대해 `ps -p <pid> -o ppid=`를 실행하여 부모 프로세스가 Iris인지 확인한다.
이전 방식으로 복원하려면 plist 이름을 복원하고 `launchctl bootstrap gui/$UID <plist>`를 실행한다.

## 사용법

개발 환경은 터미널 두 개에서 실행한다.

```
pnpm dev # 서버 4291 (--watch)
pnpm dev:app # 앱, 4291에 붙음
```

CLI·MCP를 개발 환경에 연결할 때는 같은 포트와 상태 폴더를 지정한다.

```
IRIS_PORT=4291 IRIS_STATE_DIR=$HOME/.iris-dev node bin/iris-browser.mjs tabs
```

`iris-browser`를 어느 위치에서나 호출하려면 링크를 직접 만든다. 저장소와 `./setup`은 이 링크를
만들지 않는다.

```
ln -s "$PWD/bin/iris-browser.mjs" ~/.local/bin/iris-browser
```

설치 앱에 변경 사항을 반영할 때는 다음 명령을 실행한다.

```
pnpm install:app # 종료 → 빌드 → 교체 → 실행
```

quit·build·ditto를 수동으로 반복하면 일부 단계를 누락하여 이전 코드를 검사할 수 있다.
`server/`만 수정했어도 앱을 재시작해야 반영된다. 서버는 앱의 자식 프로세스로 함께 시작된다.

## 앱 중단 시간 최소화

설치 앱은 사용자가 현재 사용하는 도구이므로 작업 중 중단 시간을 최소화한다.

- 빌드를 끝낸 뒤 종료한다. 빌드는 `dist/`에만 쓰므로 앱을 켜 둔 채 실행할 수 있다.
  먼저 종료하면 빌드 시간인 1~2분 동안 앱을 쓸 수 없다. `pnpm install:app`은 빌드와 산출물 확인을
  마친 뒤 앱을 종료하여 중단 시간을 교체·재실행에 필요한 몇 초로 줄인다. 빌드 실패 시에는
  앱을 종료하지 않는다.
- 교체 실패 시 복원할 수 있도록 기존 앱을 보관한다. 기존 앱을 먼저 삭제하면 복사 실패 시
  `/Applications`에 불완전한 앱만 남아 실행할 수 없다. 새 앱의 복사가 끝난 뒤 기존 앱을 삭제하고,
  실패하면 기존 앱을 복원한다.
- 실행 여부는 실제 상태로 확인한다. 고정 시간(`sleep 5`) 동안 기다리지 않고, 프로세스가
  실행되면 대기를 끝낸다.
- 서버만 수정한 경우 앱 종료를 피한다. 서버가 재시작하면 앱은 WS로 다시 연결한다.
  서버가 중단된 동안 앱 창을 닫지 않는다. 재연결 재시도 중 창이 사라지면 메인 프로세스가
  종료될 수 있다(`loadWithRetry` 주석 참조).
- 서버 재시작은 관리 주체를 통해 수행한다. 앱이 관리하는 서버는 앱을 재시작한다.
  `kill`이나 `pkill -f "node server/index.js"`를 사용하지 않는다. 후자는 절대경로로 실행된
  프로세스를 찾지 못하며, 두 방식 모두 종료되지 않은 서버 프로세스를 남길 수 있다.
  이전 launchd 잡이 남은 기기는 먼저 `launchctl bootout gui/$UID/<잡>`을 실행한다.
  잡이 실행 중이면 KeepAlive가 종료된 서버를 즉시 다시 실행한다.

## 검증

서버 로그에서 현재 연결된 실행기를 확인한다.

```
[cdp] 실행기 등록 — /Applications/Iris.app/Contents/MacOS/Iris (pid 28873)
[cdp] 실행기 중복 등록 거절 — 이미 …가 붙어 있고 …가 또 왔다
```

QA 회차는 설치 앱에서 실행한다. 개발 인스턴스의 결과는 회차 증거로 사용하지 않는다.
번들과 소스가 다를 수 있어 그 차이가 결과에 미친 영향을 구별할 수 없기 때문이다.
