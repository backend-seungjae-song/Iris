# 메모랩

## 메모랩과 심플 메모

```
메모랩 여러 메모 방식을 한 곳에서
 상황 묶음 · 나눔 · 할 일 · 회의 · 공부 · 준비
 보기 흐름 · 갈래 · 이음 · 낱말
심플 메모 Iris 의 memo capability. rail 라벨은 「메모」 그대로
```

심플 메모와 메모랩은 서로 다른 기능이다. 심플 메모는 한 칸에 글을 적고, 메모랩은 조각을 만들어
여러 보기로 확인한다.

## 구성 위치

```
지면 web/memolab/ (index.html · app.js · store.js · terms.js · words.js · style.css)
저장 server/memolab-store.js → ~/.iris/memolab.json · ~/.iris/memolab-ui.json
라우트 server/http-handler.js 의 /memolab-state · /memolab-ui
문 web/js/devtool/memolab-screen.js (rail 자리의 iframe)
표 web/js/core/capabilities.js 의 memolab 줄 · web/js/core/rail-items.js 의 memolab 줄
검사 bin/smoke/sections/memolab.mjs · bin/memolab-labels.mjs
여는 곳 rail 「메모랩」 · http://127.0.0.1:4271/memolab/
```

화면 자체는 앱 셸이 아니다. Iris 서버가 `web/` 아래에서 그대로 제공하는 단일 페이지이며 rail 에도
등록된다. capability 표의 `page`·`routes` 에 두 속성을 함께 등록한다. rail 에는 화면을 여는 iframe
하나가 등록된다.

## 용어 체계

하나의 개념에는 하나의 용어만 사용한다. 용어를 혼용했을 때 다음과 같은 중복이 발생했다.

```
자리 조각이 들어가는 곳 · 공부의 위치 표시 · 마인드맵 좌표 · 그냥 곳 172회
칸 모양 이름 · 조각이 들어가는 곳 176회
갈래 모양 이름 · 흐름의 가로줄 22회
묶음 분류 이름 · 그 분류 안의 한 묶음 13회
```

용어의 정본은 `web/memolab/app.js` 의 `TERMS` 하나다. 말뜻 화면과 툴팁은 모두 이 정본을 사용한다.
두 곳에 따로 정의하면 한쪽만 수정되어 화면의 용어가 일치하지 않을 수 있다.

```
판 메모 한 벌
조각 적은 한 장
분류 탭 하나
 칸 분류 칸이 있다 묶음 나눔 할 일 회의 공부 준비 흐름
 그림 분류 칸이 없다 갈래 이음 마인드맵
칸 조각이 들어가는 곳 그대로 내 말로 의문 그래서 나는
더미 아직 어느 칸에도 안 놓은 조각
위치 공부에서 조각에 찍는 자리 표시 2-2 3-5
덩어리 묶음 분류 안의 한 묶음
줄 흐름의 가로줄
단계 흐름의 세로 칸
놓은 곳 마인드맵에서 끌어다 둔 자리
보관함 판에 넣기 전에 흘려 두는 판
```

다음 용어는 의미가 겹치지 않도록 구분했다.

```
모양 이름 '칸' → '기본' 그 말은 조각이 들어가는 곳이 가져간다
공부의 '＋ 자리' → '＋ 위치' '지금 위치' '위치별 한 줄' 이 이미 그 말을 쓴다
흐름의 '갈래' → '줄' 모양 이름 '갈래' 는 그대로
묶음 안의 '묶음 1' → '덩어리 1'
'아직 안 놓은 것' → '더미' 두 말로 부르던 것을 하나로
```

행동형 이름은 사용하지 않는다. 「담는 분류」 대신 「칸 분류」를 사용한다.

조각의 배치는 분류마다 독립적이다. 공부에서 의문에 넣어도 회의 탭에서는 여전히 더미다.
`place[frame][pieceId]` 가 분류별로 존재하기 때문이다.

말뜻 화면은 도구 줄의 「말뜻」 단추로 연다. 툴팁은 `tip(낱말)` 로만 추가한다. 직접 작성하면 용어 표와
달라질 수 있다.

## 보기 추가 규칙

한 판에는 두 축이 있다. `kind` 는 판의 사용 상황이고, `view` 는 같은 조각을 표시하는 방식이다.
배치는 두 값을 결합한 `frame` 을 키로 저장한다.

보기와 키의 대응표는 `store.js` 의 `FRAME_OF` 하나다. 화면은 `Store.FRAME_OF` 를 사용한다.
같은 표를 화면에도 정의하면 한쪽만 수정될 수 있다. 그러면 판을 다시 열 때 `migrate` 가 키를 찾지
못해 다른 칸을 표시한다. 단어 보기에 이 문제가 발생했다.

「보기마다 store 가 place 열쇠를 안다」 검사는 `app.js` 의 `VIEWS` 이름을 store 의 표와 비교한다.
화면에 같은 표가 다시 정의되어 있어도 실패한다.

## 위치 묶음과 단어 보기

```
자리 묶음 공부 칸 안을 조각의 자리(loc)별로 한 겹 더 나눈다
 묶음 머리를 누르거나 거기에 놓으면 칸과 자리가 함께 바뀐다
 자리 딱지는 놓인 카드에서만 접는다 — 더미 카드에는 남겨야
 없던 자리를 새로 적을 길이 있다
마인드맵 토씨·어미를 떼고 남은 낱말이 같은 조각끼리 한 가지로
 형태소 분석기 없이 꼬리 목록을 긴 것부터 떼는 방식
 두 조각 이상에 든 낱말만 가지가 된다
 품는 낱말끼리는 접고, 조각 집합이 같은 가지끼리는 합친다
```

마인드맵은 목록이 아니라 위치와 선으로 관계를 나타내는 그림이다. 세로 목록으로 표시하면 묶음은
확인할 수 있지만, 한 조각이 두 가지에 연결된 관계를 바로 확인할 수 없다.

```
가운데 이 판
둘레 가지 — 누르면 그 가지에 안 걸린 것은 흐려진다
바깥 조각 — 두 가지 이상에 걸린 것은 노란 테두리와 ＋N
선 가운데→가지는 굵게, 가지→조각은 가늘게, 걸친 것은 노랗게
```

각도는 렌더링 전에 정하고 반지름은 렌더링 후에 정한다. 겹침 여부를 판정하려면 DOM 에 추가한 뒤
확인한 칸 크기가 필요하다. 크기를 178·330 으로 고정했을 때는 조각이 늘수록 겹쳤고 간격을 늘릴 수
없었다.

```
1 가지 고리 가지들의 폭을 다 더해 두 겹에 담길 둘레부터 잡는다
 안쪽 겹부터 각도가 비는 자리에 넣고, 빈 자리가 없으면 한 겹 바깥으로
2 조각 고리 같은 규칙으로, 가장 바깥 가지보다 밖에서 시작해서
3 남은 겹침 겹친 짝을 서로 밀어 뗀다. 가운데는 안 움직이고 가지는 조금만
4 담을 자리 가운데를 0,0 으로 계산하므로 음수가 나온다. 그만큼 밀어 넣는다
```

겹 사이의 간격은 해당 겹에서 가장 높은 요소를 기준으로 정한다. 판 전체에서 가장 큰 카드 하나를
기준으로 모든 겹의 간격을 정하면 짧은 카드만 있는 겹까지 밀려 지도가 불필요하게 커진다.

가지 고리의 시작 반지름을 최솟값으로 정하면 가지 40개가 가운데에 여섯 겹으로 겹쳐 글자를 읽을 수
없다. 확인 결과를 바탕으로 폭의 합에서 반지름을 계산하면 가지가 고리 형태로 배치되고 안쪽 공간이
확보된다.

배율은 사용자가 정한다. 창 너비 459 에서 자동 맞춤을 적용하면 0.6 배가 적용되어 카드가 101px 로
축소되었다. 축소와 겹침 방지는 별도의 동작이다.

```
－ ＋ 1.25 배씩
맞춤 전체가 한 화면에 들어오게
⌘·Ctrl+굴림 잡고 있는 점을 그 자리에 두고 배율
그냥 굴림 지도를 민다
```

배율은 `Store.ui('mapZoom')` 에 저장된다. 브라우저 저장소가 아니라 서버 파일에 저장되며 내보내기
데이터에는 포함되지 않는다. 가지를 눌러 필터링하여 다시 렌더링해도 배율과 이동 위치를 유지한다.

지도 이동과 요소 이동은 같은 포인터 동작을 사용하므로 선택한 대상에 따라 구분한다.

```
빈 데를 잡고 끌기 지도가 밀린다
조각·가지를 잡고 끌기 그것이 옮겨진다
⌘·Ctrl 을 누른 채 끌기 조각 위에서도 지도가 밀린다
4px 아래로 움직임 옮기기가 아니라 누른 것 — 조각은 고치기, 가지는 거르기
```

이동한 위치는 `b.map` 에 저장한다. 키는 조각이면 해당 id, 가지면 `w:낱말` 이고 값은 가운데를 0,0
으로 본 x·y 다. 화면 좌표로 저장하면 창이나 주변 요소가 바뀔 때마다 위치가 어긋난다. 사용자가
옮긴 요소에는 고리 계산과 겹침 해소 이동을 적용하지 않는다. 모든 이동을 취소하려면 「자리 되돌리기」를
사용한다. 이동한 요소가 없으면 이 단추를 표시하지 않는다.

지도에서는 조각을 밖으로 이동할 수 없다. 끌기에 「다른 탭의 칸으로 보내기」 동작을 할당하면 지도
안에서 위치를 바꿀 수 없다. 따라서 `pieceNode` 가 `frame === 'word'` 일 때 `dragSource` 를 추가하지
않고, 지도 안의 이동은 HTML5 끌기 대신 포인터로 직접 처리한다.

꼬리 목록(`TAIL`)과 흔한 단어 목록(`SKIP`)은 화면 문구가 아니라 데이터다. 라벨체 검사는 해당 배열만
제외하도록 시작 줄에 `낱말 데이터` 표시를 사용하고, 배열이 끝난 뒤에는 검사를 다시 적용한다.

## 좁은 창 레이아웃

영상 옆에 메모랩을 표시할 수 있도록 너비 380~600px 범위의 창을 지원한다.

```
760px 아래 레일이 빠지고 판 이름 옆 ☰ 로 덮어 연다. 판을 고르면 스스로 닫힘
 더미와 칸이 옆이 아니라 위아래로 쌓임 — 적는 칸이 맨 위
 탭 열 개가 한 줄로 남고 옆으로 밀림. 지금 탭은 보이는 자리로 옮김
 나눔만 한 줄로 안 세움 — 네 칸의 자리가 곧 뜻이라 2×2 를 지킴
460px 아래 더미가 더 짧아지고 딱지·자리 칸이 좁아짐
```

화면 위쪽의 요소도 함께 줄였다.

```
안내 줄 조각이 하나라도 있으면 안 뜬다
출처 · 한 줄 각자 한 줄씩 쓰던 입력칸을 딱지 하나로. 누르면 그 자리에서 고친다
위치별 한 줄 접을 수 있다. 접힘은 화면 취향이라 서버의 `ui` 칸에 남는다
```

확인 결과(창 420px)

```
칸 너비 96 → 420
칸 위 높이 560 → 395 (안내 223 · 출처 61 · 한 줄 61 · 덮기 60 · 위치 155)
탭 줄 110 → 38
```

## 가로 판 레이아웃

카드가 쌓여 칸과 판이 세로로 길어지면 편집 중 위아래로 이동해야 하고 칸의 내용을 한 화면에서
확인하기 어렵다. 칸을 화면 높이에 맞추고 넘치는 내용을 옆으로 배치하여 판이 가로로 확장되게 한다.

```
가로로 세움 묶음 · 회의 · 준비 · 공부
그대로 둠 나눔 — 네 칸의 자리가 곧 뜻이라 한 줄로 세우면 축이 사라진다
 할 일 — 오늘 띠가 시각 순서라 세로가 그 자체로 뜻이다
760px 아래 세로로 되돌린다. 그 폭에서는 한 칸도 다 못 보여 준다
```

옆으로 배치된 줄만큼 칸의 너비도 늘어나야 한다. flex 는 칸의 내용 너비를 배치 전 한 줄 기준으로
계산하여 칸이 내용보다 좁아질 수 있다. 따라서 렌더링 후 너비를 확인해 적용한다(`fitWideSlots`).

한 위치에 카드가 많으면 묶음 하나가 칸 높이를 넘을 수 있다. 묶음은 나누어 옆 줄로 보낼 수 없으므로
해당 묶음 내부에 스크롤을 적용하고 묶음 머리는 고정한다. 넘친 내용을 자르면 해당 카드를 확인할 수
없다.

## 가장자리 끌기 동작

끌기 중에는 일반 스크롤을 사용할 수 없어 화면 밖의 칸에 놓을 수 없다. 포인터가 칸의 가장자리
72px 안에 있는 동안 해당 칸을 스크롤한다.

스크롤 대상은 포인터 아래에서 상위 요소 방향으로 탐색한 첫 스크롤 영역이다. 칸 안에서는 칸을
스크롤하고 칸 밖에서는 판 전체를 스크롤한다. 스크롤 끝에 도달한 칸은 건너뛰고 상위 영역을 사용한다.

## 끌기 중 대상 칸 표시

칸이 가로 스크롤로 화면 밖에 있으면 해당 칸에 조각을 놓을 수 없다. 이 문제로 공부의 네 칸 중
화면에 보이는 칸에만 조각을 놓을 수 있었다.

끌기 중에는 판 위쪽에 별도 영역을 만들고 현재 탭의 칸을 모두 표시한다.

```
공부 그대로 · 내 말로 · 의문 · 그래서 나는
회의 정한 것 · 할 것 · 안 정한 것 · 들은 것 · 의문
나눔 지금 · 날짜 잡기 · 몰아서 한 번에 · 빼기
할 일 할 일 · 기다리는 중 · 언젠가 · 끝
준비 끝나면 정해져 있을 것 · 꺼낼 것 · 물어볼 것 · 오늘은 안 꺼낼 것
묶음 사람이 만든 묶음 전부
흐름 단계마다 한 칸(갈래가 둘 이상이면 「단계 · 갈래」)
```

현재 탭의 칸만 표시한다. 다른 탭의 칸까지 표시하면 공부에서 끌 때 나눔·할 일·회의의 칸도 함께
나타난다. 이동 대상은 현재 보고 있는 프레임 안으로 제한한다.

이전에는 탭 줄을 놓기 영역으로 사용했다. 탭 하나는 해당 프레임의 첫 칸만 대상으로 삼으므로
「공부」에 놓으면 항상 「그대로」로 이동했다. 탭 하나로 프레임 전체를 대표할 수 없기 때문이다.

칸이 하나뿐인 프레임은 표시하지 않는다. 갈래·이음·마인드맵도 대상에서 제외한다. 선과 위치가 의미를
구성하므로 「넣을 칸」이 성립하지 않는다.

대상 칸 영역은 판을 덮지 않고 별도 공간에 배치한다. 판 위에 겹치면 아래의 칸을 가려 끌기 중
「눈앞의 칸에 놓기」를 사용할 수 없다. 공간을 분리하면 두 놓기 동작을 모두 사용할 수 있다.

대상 칸은 렌더링할 때 미리 생성해야 한다. 끌기가 시작된 뒤 생성하면 놓기 영역으로 인식되지 않는다.
CSS(`body.dragging`)는 미리 생성한 영역의 표시 상태만 바꾼다. 끌기 중 다시 렌더링하면 선택한 조각이
사라져 끌기가 중단된다.

의문 칸 배치 후처리(`afterPut`)는 이 경로에서도 실행한다. 두 놓기 경로 중 한쪽에서만 실행하면 사용한
경로에 따라 의문 목록이 달라진다.

## 조각 이동과 편집

```
끌기 옮기기 — 칸에서 칸으로, 자리 묶음 머리에 놓으면 자리까지 함께
누르기 고치기 — 카드 안에서 바로. 나가면 담기고 Esc 면 버린다
 여러 줄이 흔하므로 Enter 는 줄바꿈이고 ⌘Enter 가 담기다
```

누르기는 이전에 「집기」 동작으로 사용되어, 조각을 선택한 뒤 칸을 눌러 이동했다. 이 방식에는 작성한
내용을 편집하는 경로가 없었다. 이동은 끌기로 처리하므로 누르기는 편집에 사용한다.

## 설치 앱과 개발 환경의 데이터 구분

```
쓰는 곳 http://127.0.0.1:4271/memolab/ 설치된 앱. 저장은 ~/.iris/memolab.json
개발용 http://127.0.0.1:4291/memolab/ 저장은 ~/.iris-dev/. 확인용으로만 띄운다
```

`pnpm install:app` 으로 반영한다.

## 저장 보장

데이터 손실을 막으려면 네 가지 손실 경로를 검사해야 한다. 기존 메모랩 검사 8개는 소스 구조만
검사하여 이 손실 경로가 재현되어도 모두 통과했다.

```
받아 오는 사이의 편집 poll 이 요청 전에만 dirty 를 보고, 응답을 담을 때는 안 봤다
 그 사이에 적은 조각이 경고 없이 사라지고 rev 까지 새것이 되어
 서버의 409 가 막을 기회조차 없었다
저장이 죽은 뒤 stop 은 경고 한 번뿐인데 편집 함수는 계속 메모리를 바꿨다
서버 문턱 rev 를 안 보내면 충돌 검사를 건너뛰었고 빈 PUT 이 200 이었다
불러오기 state 를 먼저 갈아 끼우고 나서 판을 훑었다
지운 조각 갈래는 칸 이름이 부모 조각 id 라 자식 참조가 남았다
```

각 손실 경로는 다음과 같이 방지한다.

```
세대(gen) persist 마다 오른다. 받아 온 것을 담기 전에 요청 시작 때와 같은지 본다
 dirty 만으로는 모자라다 — 요청이 도는 동안 적고 저장까지 끝나면
 dirty 가 다시 false 라서 그 손질이 지워진다
저장 멈춤 띠 못 닫는 띠로 세우고 그 자리에 파일로 내려받기를 둔다
 경고창 한 번은 닫으면 사라지고, 그 뒤 적은 것이 전부 새로고침에서 없어진다
서버 rev 가 정수이고 판 모양이 맞을 때만 담는다. 아니면 400
불러오기 다 세우고 검증한 뒤에 한 번에 갈아 끼운다
지우기 열쇠로도 지우고 값으로 가리키는 자리도 지운다
```

`bin/memolab-race.mjs` 는 동작을 실행하여 결과를 확인한다. 가짜 fetch·document 로 store.js 를
구성하고 해당 순서를 실행한 뒤 조각이 남아 있는지 검사한다. 서버 검사는 임시 상태 폴더에서 실제
모듈을 호출하므로 사용자 파일을 변경하지 않는다.

다음 회귀 조건에서 검사 실패를 확인했다.

```

세대만 제거 회차 2 실패 — dirty 만으로는 못 막는다는 증거
불러오기를 옛 순서로 회차 3 실패
지울 때 값 참조를 안 봄 회차 4 실패
서버 문턱 제거 회차 5 실패
```

## 저장 이력 관리

덮어쓰기 전에 현재 상태를 `<상태폴더>/memolab-history/` 에 저장한다. 파일 이름은
`r000022-T16-52-26-088Z.json` 형식이며 최대 200개를 보관하고 오래된 파일부터 삭제한다.

```
rename 쓰다가 끊겨도 반쪽이 안 남는다
memolab-history 아까 것을 다시 볼 수 있다
```

원자적 저장과 저장 이력은 서로 다른 요구 사항이다. rename 만 사용하면 덮어쓴 뒤 복원할 백업본,
스냅샷, 로그 본문이 없다.

이력 저장에 실패해도 현재 상태 저장은 계속한다. 이력 오류 때문에 현재 변경 사항까지 저장하지 못하는
상황을 방지하기 위해서다.

## 서버 저장을 선택한 이유

브라우저 localStorage 를 사용하면 주소가 조금만 달라도 다른 판이 표시된다. `localhost` 와
`127.0.0.1` 도 서로 다른 저장소이고, 다른 기기에서는 데이터가 없다. 서버 파일 하나를 정본으로
사용하면 어느 기기에서 열어도 같은 판을 표시한다.

```
읽기 GET /memolab-state → { rev, data }
 GET /memolab-state?rev=N → 같으면 { same: true } (본문 생략)
쓰기 PUT /memolab-state { rev, data }
 rev 가 어긋나면 409 — 두 곳에서 연 판이 서로를 조용히 지우지 않게
```

화면 코드에는 브라우저 저장소를 사용하지 않는다. 판 데이터와 화면 설정(레일 접힘)을 모두 서버
파일의 `ui` 칸에 저장한다. 주소에 따라 저장소가 갈리는 것이 원인이기 때문이다. `ui` 는
`exportJSON` 에 포함하지 않는다. 내보내기는 판을 다른 사람에게 전달하는 기능이고 창 상태는 전달
대상이 아니다.

「메모랩 저장은 서버 한 파일이다」 검사가 화면의 네 파일 전체에서 `localStorage`·`sessionStorage`
사용을 찾는다. store.js 만 검사하면 다른 파일에서 브라우저 저장소를 사용해도 발견하지 못한다.

쓰기는 임시 파일에 기록한 뒤 rename 한다. 원본을 직접 덮어쓰면 쓰는 도중 중단될 때 파일이
불완전한 상태로 남는다.

화면의 읽기 경로는 모두 동기다. 처음 한 번만 서버에서 받아 오고(`Store.ready`) 그 뒤로는 메모리를
읽는다. 쓰기는 400ms 동안 모아서 전송한다. 10초마다 rev 만 조회해 다른 곳의 변경을 반영하며,
전송할 변경이 남아 있으면 조회를 건너뛴다.

## 셔틀 제외

`bin/smoke/core.mjs` 의 `WEB_SHUTTLE_EXCLUDES` 에 메모랩의 네 파일이 등록되어 있다. 렌더러 검사
대상에 포함하면 특정 형태가 어디에도 없어야 한다고 판정하는 검사들이 메모랩 화면까지 검사한다.

제외만 하면 아무 검사도 적용되지 않으므로 메모랩은 자체 검사를 갖는다. 검사 항목은 저장이 서버
파일인지, 서버가 그 경로를 실제로 처리하는지, rename 을 거치는지, 로드 순서, 데이터를 받은 뒤에
렌더링하는지, 문구 형식이다.

## 앱 반영 절차

설치된 앱은 저장소가 아니라 번들 안의 사본(`app.asar.unpacked/`)을 읽는다. 변경 사항은
`pnpm install:app` 으로 반영한다.

이 트리에서 여러 세션이 동시에 작업하므로 `install:app` 이 언제 실행될지 알 수 없다. 저장소에
미완성 상태를 저장하면 그대로 실제 앱에 반영된다. 새 파일이 번들에 포함되지 않은 채 그 파일을
import 하는 파일만 반영되어, 서버가 `ERR_MODULE_NOT_FOUND` 로 종료되고 Iris 를 몇 분 동안 사용할
수 없었다.

## 저장 위치가 둘인 이유

판과 창 상태를 서로 다른 파일에 저장한다.

판 (`memolab.json`)
 조각·칸·묶음·순서
 rev 로 충돌을 판정하고 이전본 200개를 보관한다

창 상태 (`memolab-ui.json`)
 마인드맵 배율
 접힘
 현재 연 판
 충돌 판정 없음
 나중에 저장한 값을 사용한다

한 파일에 저장했을 때 세 가지 문제가 있었다.
 배율만 바꿔도 조각 100여 장을 함께 전송한다
 두 창이 서로 다른 판을 열면 저장이 충돌해 한쪽이 중단된다
 다른 창에서 판을 바꾸면 이 창의 판도 함께 바뀐다

변경 단위가 다른 데이터는 저장 위치도 분리한다.

이전 판 문서에 남아 있는 배율·접힘·연 판은 처음 열 때 한 번 가져오되, 값을 복사해서 가져온다.
같은 객체를 전달하면 배율을 바꿀 때 판 문서도 함께 바뀌고 다음 저장에서 판에 포함되어 전송된다.
설치된 앱에서 이 문제가 발생했다.

판 문서에 저장하는 항목은 둘뿐이다.
 boards
 v

이전 문서에 남아 있는 ui · current 항목은 다음 저장에서 제거된다.

## 마인드맵 가지의 처리

자동으로 추출한 가지는 후보이며, 무엇을 주제로 삼을지는 사용자가 정한다.

가지를 누르면 위쪽에 편집 줄이 표시된다.
 이름 바꾸기

영문에 붙은 조사도 분리한다.
 이전에는 AI가 · AI는 이 각각 다른 가지였고 AI 자체는 두 글자라 제외되었다
 현재는 AI · SEO · GEO 가 각각 하나의 가지다

## Iris 안에서 열기

 나갈 때 제거하지 않는다
 제거하면 다시 열 때마다 새로 로드되어 작성 중이던 내용이 사라진다

「따로 열기」로 창 하나를 전체로 사용할 수 있다. 주소가 같으므로 같은 저장소를 사용한다.

capability 표에 두 속성을 추가했다.
 page 이 기능이 단독으로 사용하는 화면 디렉터리
 routes 그 화면이 사용하는 HTTP 경로

검사는 네 가지를 확인한다.
 그 디렉터리가 실재하는가
 앱 셸이나 다른 기능이 그 안의 파일을 정적으로 가져오지 않는가
 등록한 경로가 실제로 라우팅되고 그 처리기가 이 기능의 서버 파일에 있는가
 그 화면이 실제로 그 경로를 호출하는가

## 화면 파일 구성

`store.js` 저장 계층
`words.js` 단어 추출과 가지 계산
`terms.js` 용어 정본
`app.js` 화면

화면은 모듈 하나(`app.js`)만 로드한다.
 로드 순서는 import 가 결정한다
 전역 이름과 적재 순서를 직접 맞출 필요가 없다
 `Store` 도 전역이 아니다

`words.js` 는 DOM 과 Store 를 참조하지 않는다.
 판 하나를 입력받아 값을 반환하는 순수 계산이다
 따라서 `bin/memolab-words.mjs` 가 앱을 실행하지 않고 직접 호출한다
 이전에는 app.js 에서 해당 구간을 기준점으로 잘라 사용했다

## 판 묶음 보기

왼쪽 줄 위의 전환 단추 두 개로 선택한다. 한 번에 한 기준으로만 묶는다.

폴더
 사용자가 지정한다. 판 이름 옆 칸에 이름을 입력하면 그 폴더에 포함된다
 이미 사용한 이름은 목록에서 선택한다
 폴더에 넣지 않은 판은 「폴더 없음」으로 모인다
 폴더가 하나도 없으면 묶지 않고 목록으로 표시한다

날짜
 자동으로 생성된다. 마지막으로 작성한 날짜로 묶는다
 아직 아무것도 작성하지 않은 판은 만든 날짜로 묶는다
 오늘 · 어제만 이름으로 표시하고 나머지는 「9월 4일」 형식으로 표시한다

두 기준 모두 최근 항목이 위에 오고, 폴더 없음은 항상 맨 아래에 둔다.

보관함은 묶음 밖에 표시한다. 어느 묶음을 접어도 접근할 수 있어야 하기 때문이다.

접기
 묶음 머리의 ▾ 를 누르면 그 묶음이 접힌다
 접혀 있어도 현재 보고 있는 판 한 줄은 표시한다
 줄을 56px 로 접으면 묶음 머리와 전환 단추가 함께 숨겨지고 접힘 상태도 무시한다. 펼 수 있는 영역이 없기 때문이다

폴더는 이름 자체가 폴더다.
 별도의 폴더 목록을 두지 않는다
 마지막 판이 빠지면 그 폴더도 함께 사라지므로 정리할 항목이 남지 않는다
 대신 폴더 이름을 바꾸려면 그 안의 판을 전부 수정해야 한다

저장 위치
 `b.folder` 판 문서 (판의 내용)
 `railBy` · `groupShut` 창 상태 (사용자의 표시 설정)

검사: `bin/memolab-groups.mjs`
