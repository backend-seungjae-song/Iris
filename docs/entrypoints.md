# 진입점

사용 중인 코드는 진입점에서 참조되어야 한다. 참조되지 않는 고아 파일은 삭제한다.

`bin/graph.mjs`가 참조 경로를 검사한다. 대부분의 진입점은 실제 실행 구성을 읽어 찾는다.
대상은 `package.json`의 scripts, html의 `<script>`와 import, 셸 스크립트의 `node X`,
자식 프로세스로 실행하는 코드 경로, 러너가 폴더를 순회하며 실행하는 파일이다.
따라서 스크립트를 추가하거나 삭제해도 이 문서를 수정할 필요가 없다.

이 문서는 코드에서 호출하지 않는 진입점만 관리한다. 사용자가 수동으로 실행하는 도구는
호출 코드로 찾을 수 없으므로 아래 표에 등록한다.

## 진입점 등록의 설계 이유

`#!/usr/bin/env node`는 사용 여부와 무관하게 추가할 수 있으므로 진입점 판정 기준으로 쓰지 않는다.
셔뱅만으로 진입점을 인정하면 사용하지 않는 도구도 고아 파일로 판정할 수 없다.
수동 실행 도구는 명시적으로 한 행씩 등록한다.

## 수동 실행 진입점

첫 열의 경로를 기준으로 판정한다. 표에 등록되어 있고 파일이 실제로 존재해야 진입점으로 인정한다.

| 경로 | 용도 | 실행 방법 |
| --- | --- | --- |
| `setup` | 최초 설치 | 저장소를 받은 직후 `./setup` 실행 |
| `bin/graph.mjs` | 고아 파일·간선·진입점 조회 | `node bin/graph.mjs` |
| `bin/importers.mjs` | 지정한 파일의 호출 파일 목록 조회 | `node bin/importers.mjs <파일>`. 계약 헤더에 기재된 조사 명령 |
| `scripts/probe/fs-tree.mjs` | 파일 트리 응답 확인 | `node scripts/probe/fs-tree.mjs <경로>` |
| `scripts/probe/space-binding.mjs` | 스페이스 키 해석 결과 확인 | `node scripts/probe/space-binding.mjs <dev> <ino>` |
| `scripts/probe/window-raise.mjs` | 창 활성화 확인 | `node scripts/probe/window-raise.mjs` |
| `bin/frame-purity.mjs` | 앱 셸이 기능 코드에 의존하는 위치 집계 | `node bin/frame-purity.mjs`. 결과가 0인지 확인 |
| `scripts/parallel-proof.sh` | 두 작업자가 기능을 각각 수정한 뒤 병합하는 실험 | `bash scripts/parallel-proof.sh` |

## 진입점 목록 검증

그래프는 다음 세 경우를 모두 검사하여 목록과 코드가 일치하는지 확인한다.

- `표에 있는데 파일이 없다`: 삭제한 도구가 표에 남아 있다.
- `표에 있는데 코드가 이미 부른다`: 수동 실행 전용이 아닌 파일이 표에 남아 있다.
  이 행을 유지하면 나중에 호출 코드가 사라져도 고아 파일로 판정할 수 없다.
- `파일이 있는데 표에도 없고 아무도 안 부른다`: 등록되거나 참조되지 않은 고아 파일이다.

`node bin/graph.mjs --check`가 세 경우를 판정한다. `pnpm test`는 smoke 직후 이 명령을 실행하고,
`pnpm release-audit`도 배포 전 전체 검사에서 실행한다. 실행 시간은 0.7초이므로 빠른 검사
과정에서도 제외하지 않는다.

## 코드 폴더의 집계 누락 검사

그래프는 `CODE_ROOTS`에 지정된 코드 폴더만 검색한다. 새 코드 폴더를 목록에 추가하지 않으면
폴더 전체가 집계에서 제외되어 고아 파일을 찾을 수 없다. `--check`의 「코드 폴더를 다 센다」가
저장소의 실제 코드 폴더를 모두 포함하는지 별도로 검사한다.

## CSS 이름 변경의 불일치 검사

기능별로 CSS를 분리할 때는 이를 참조하는 코드의 이름도 함께 바꿔야 한다. CSS 이름만 바꾸고
JS 참조를 그대로 두면 화면의 헤더·구획·칩·빈 상태에 스타일이 적용되지 않는다.

파일과 import가 존재하므로 고아 파일 검사와 사용하지 않는 export 검사로는 이 문제를 찾을 수
없다. 오래된 사본으로 두 파일이 복원되어 이름 열한 개의 스타일 정의가 누락된 사례가 있다.

`--check`의 「화면이 부르는 지면 이름이 옮기다 만 채로 남아 있지 않다」가 다음 세 조건을
모두 만족하는 이름을 검사한다. 변경 여부가 불명확하면 통과시킨다.

1. JS·HTML에 리터럴로 적힌 class 이름이다. `${...}`로 조합한 이름은 제외한다.
2. `web/css`와 인라인 `<style>`에 해당 이름의 정의가 없다.
3. CSS에 접두사만 다르고 나머지는 같은 이름이 정의되어 있다.

셋째 조건만으로는 `bmk-t`와 `sv-t`처럼 우연히 일치하는 이름도 포함된다. 한 접두사의 이름
셋 이상이 동일한 다른 접두사의 이름과 대응할 때만 이름 변경으로 판정한다.
CSS 파일 수나 화면 파일 수가 최소 기준보다 적으면 통과 대신 「못 잰 것」으로 처리한다.
검사 대상이 모두 제외되어 나온 0건을 실제 위반 0건과 구별하기 위해서다.
