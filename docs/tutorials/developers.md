# 개발자 튜토리얼: 웹페이지 수정을 요청하고 확인하기

로컬 웹앱에서 수정할 요소를 선택하고 에이전트에게 요청한 뒤, 화면과 코드 변경을 확인해 보세요. Iris 자체의 코드를 수정하는 개발 환경도 아래에서 안내합니다.

## 1. 앱과 에이전트 준비하기

[설치 안내](../../README.md#설치하기)에 따라 Iris를 설치하세요. Claude Code 또는 Codex CLI의 설치와 로그인을 먼저 완료하고 `./setup`에서 Iris 도구 등록에 동의합니다. 이미 설치했다면 `./setup --check`로 준비 상태를 확인할 수 있습니다.

왼쪽 **작업 → SPACES**에서 웹앱 프로젝트를 선택합니다. 새 프로젝트는 **SPACES** 옆의 `+`에서 추가하세요. 터미널 탭의 `+`에서 **새 탭 — Claude 세션** 또는 **새 탭 — Codex 세션**을 선택하고, **AGENTS**에서 사용할 세션을 선택합니다.

## 2. 로컬 웹앱 열기

프로젝트에서 정한 개발 서버 명령을 터미널에서 실행하세요. 실행 결과에 표시된 로컬 주소를 Iris 브라우저의 새 탭에 입력합니다. 프로젝트마다 실행 명령과 포트가 다르므로 해당 프로젝트의 README를 따르세요.

페이지가 열리면 수정하려는 버튼이나 문구가 보이는지 확인합니다.

## 3. 요소를 선택하고 수정 요청하기

`⌘⇧E`를 누르고 수정할 요소를 클릭하세요. 선택한 요소의 정보가 에이전트 터미널에 전달됩니다. 소스 위치를 찾을 수 있는 로컬 앱에서는 파일과 줄 번호도 함께 확인할 수 있습니다.

![지목한 영역을 표시한 캡처](../images/element-pick.png)

위 공개 페이지에서 실제로 전달된 정보 일부입니다. 이미지는 지목 결과를 기준으로 영역을 표시했습니다.

| 항목 | 전달된 값 |
|---|---|
| 페이지 | `https://github.com/backend-seungjae-song/Iris` |
| 대체 선택자 | `div.tmp-pt-3.tmp-pb-3` |
| React 컴포넌트 | `CodeViewHeader` |

공개 웹페이지에서는 컴포넌트 이름이 확인되어도 로컬 소스 파일과 줄 번호를 찾지 못할 수 있습니다.

전달된 대상을 확인하고 다음과 같이 요청하세요.

> 선택한 버튼의 문구를 ‘예약하기’로 바꿔 줘. 클릭했을 때의 동작은 유지하고, 바뀐 파일과 확인 결과를 알려 줘.

레이아웃을 설명하기 어렵다면 `⌘⇧D`로 화면 스케치를 열어 변경할 위치를 표시하세요. 에이전트가 수정한 뒤 브라우저에서 페이지를 다시 읽고 문구와 클릭 동작을 확인합니다.

## 4. 오류가 발생하는 순서 전달하기

재현할 페이지를 열고 `⌘⇧A`를 눌러 기록을 시작하세요. 문제가 생기는 클릭과 입력을 수행한 뒤 다시 `⌘⇧A`를 눌러 종료합니다.

기록에는 시작한 탭과 그 탭에서 새로 열린 탭의 조작이 포함됩니다. 종료 후 터미널에 전달된 조작 내역을 확인하고 기대한 결과와 실제 결과를 덧붙이세요.

> 검색어를 입력하고 검색 버튼을 눌렀어. 결과 목록이 나와야 하는데 로딩 표시가 계속 남아 있어. 전달된 순서로 확인하고 원인을 찾아 줘.

이 기능은 클릭·입력 등의 재현 기록을 전달합니다. 공유할 동영상을 만들려면 별도의 화면 녹화가 필요합니다. 비밀번호나 개인 정보가 필요 없는 예제로 기록하세요.

## 5. 변경 확인하기

왼쪽 **깃**에서 변경 파일과 diff를 읽고 요청한 범위의 수정인지 확인하세요. 프로젝트에서 제공하는 검사 명령을 실행한 뒤 브라우저에서 같은 작업을 반복합니다.

버튼 문구, 클릭 결과, 프로젝트 검사 결과를 확인하면 이번 수정을 마친 것입니다. 다음 작업에 필요한 내용은 스페이스의 **메모**에 남길 수 있습니다.

## 여러 에이전트에게 작업 나누기

같은 스페이스에서 터미널 탭의 `+`로 세션을 하나 더 열 수 있습니다. 수정하는 세션과 검토하는 세션의 요청을 구분해 전달하세요.

| 세션 | 요청 예시 |
|---|---|
| 수정 담당 | 선택한 버튼의 문구를 바꾸고 관련 검사를 실행해 줘. |
| 검토 담당 | 변경된 diff를 읽고 클릭 동작에 영향이 있는지 확인해 줘. |

왼쪽 **AGENTS**에서 세션을 전환하고 각 터미널의 진행 상황을 확인하세요. 요소 지목과 조작 기록을 보낼 때도 먼저 받을 세션을 선택합니다. 두 세션이 같은 파일을 동시에 수정하지 않도록 작업 범위를 정하세요.

## Iris 자체를 개발하려면

저장소의 [CLAUDE.md](../../CLAUDE.md)와 [기여 안내](../../CONTRIBUTING.md)를 먼저 읽으세요. Node.js 22 이상과 `package.json`의 pnpm 버전이 필요합니다.

저장소 루트의 터미널에서 실행합니다.

```bash
pnpm install
pnpm dev
```

두 번째 터미널에서 같은 저장소로 이동해 실행합니다.

```bash
pnpm dev:app
```

| 구분 | 설치된 앱 | 개발 환경 |
|---|---|---|
| 서버 포트 | `4271` | `4291` |
| 상태 폴더 | `~/.iris` | `~/.iris-dev` |
| 브라우저 프로필 | `Iris` | `Iris-dev` |

개발용 CLI도 같은 포트와 상태 폴더를 지정합니다.

```bash
IRIS_PORT=4291 IRIS_STATE_DIR="$HOME/.iris-dev" node bin/iris-browser.mjs tabs
```

변경한 동작을 확인한 뒤 검사를 실행하세요.

```bash
pnpm test
```

`pnpm test -- --fast`는 상태 잠금 인계, 포트 대기, 종료 시 저장에 관한 세 검사를 제외합니다. 공개 전에는 `pnpm release-audit`을 실행하세요.

앱 빌드만 하려면 `pnpm dist`를 실행합니다. 빌드한 앱은 `dist/mac-arm64/Iris.app`에 생성됩니다. 설치된 앱에 반영할 준비가 끝나면 `pnpm install:app`을 실행하세요. 빌드와 산출물 확인 후 기존 앱을 종료하고 교체·재실행하므로 사용 중인 앱도 잠시 중단됩니다.
